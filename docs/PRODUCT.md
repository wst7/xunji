# 拾回产品说明

> 本文只描述产品定位、原则与边界，不描述实现方式。
> API、数据库、模块签名与状态枚举以 [`ENGINEERING.md`](ENGINEERING.md) 为准。

**一句话：** 你不需要记住收藏了什么，只需要记住你想找什么。

## 要解决的问题

用户每天都会遇到值得保留的内容：公众号文章、技术博客、GitHub 项目、视频、研究报告。
它们通常被放进浏览器书签、微信收藏、稍后读或笔记软件，然后出现同样的困境：

- 内容分散在不同平台，收藏后很少再整理。
- 分类、标签和文件夹逐渐失效，维护成本高于收益。
- 收藏越多，越难回忆起自己收藏过什么。
- 传统搜索要求先想起标题或关键词，而不是「我记得里面讲过什么」。
- 即使使用 AI 知识库，用户仍要导入、分类、维护，才能获得价值。

用户真正需要的不是另一个存储内容的地方，而是一个能把自己过去看过的内容找回来的系统。

## 产品定位

拾回是面向个人的智能内容记忆与找回工具。用户只需要做两件事：

1. **保存**：看到有价值的内容，把链接交给拾回。
2. **找回**：未来用一句自然语言，描述自己记得的内容。

解析、摘要、关键词、切分、向量索引与关联全部由系统在后台完成。

**拾回不是：**

- 传统书签管理器
- 需要手动分类的知识库
- 以笔记编辑为核心的工具
- 需要维护标签的收藏软件
- 只给收藏列表加一个 AI 对话框的应用
- 通用网页搜索引擎

**拾回是：** 以个人历史收藏为基础，理解模糊记忆并找回相关内容的 Personal Memory Engine。

## 核心体验

用户一个月后想起：

> 之前看过一篇文章，讲的是用 AI 自动操作浏览器，好像还提到了 Playwright。

用户不需要记得标题、作者或收藏时间，只需要输入这段描述。
拾回从**该用户自己的收藏**中返回最相关的内容，并解释为什么匹配。

这是产品最重要的体验，也是所有设计取舍的起点。

## 产品原则

### 1. 保存成本接近于零

保存不要求填写标题、分类、标签或备注。粘贴链接即可。

### 2. 不要求用户维护知识库

分类、摘要、关键词与关联关系均由系统自动生成。人工整理不能成为使用产品的前提。

### 3. 优先找回，而不是管理

首页服务于搜索与保存，不以文件夹、标签云和收藏管理面板为中心。

### 4. AI 是基础设施，不是产品噱头

用户不需要选择模型、创建 Agent 或配置知识库。AI 在后台工作，用户感知到的是搜索结果质量。

### 5. 原始链接永远有价值

即使抓取、解析或索引失败，也必须保留原始链接和基本元数据。

### 6. 不能保证的事情不假装成功

保存成功不代表解析成功。解析失败、部分成功、索引失败都必须是明确状态，而不是静默成功。

## MVP 目标

V1 验证的核心问题：

> 用户是否愿意把日常遇到的有价值内容交给拾回，并在未来依靠自然语言搜索找回它们？

必须具备的能力：

1. 提交 URL 并立即创建收藏。
2. 识别常见来源并异步抓取、解析。
3. 生成摘要、关键词与语义索引。
4. 用自然语言搜索历史收藏。
5. 搜索结果展示真实匹配原因，而不是生成一段解释。
6. 解析失败时保留原始链接，并支持重新解析。
7. 识别重复收藏，避免重复处理。
8. 支持查看详情、重新解析与删除。
9. Web 与独立 iOS / Android App 均可完成主要流程。
10. 手机 App 提供系统分享入口，并在离线时把待保存链接留在本机队列中。

方向性指标（通过真实使用校准，不作为当前实测结果）：

| 指标 | 初始目标 |
|---|---|
| URL 保存成功率 | ≥ 99%（不含不可控的网络失败） |
| 基础网页解析成功率 | ≥ 90%（固定测试集） |
| 已索引内容可搜索率 | ≥ 99% |
| 搜索首屏 P95 | ≤ 3 秒 |
| 保存接口返回 | 通常 ≤ 1 秒 |
| 标准化后相同 URL 去重 | 100% |

## V1 不做什么

- 团队共享、协作与评论
- 笔记编辑器
- 人工维护的标签体系、文件夹树、双向链接图谱
- 完整离线浏览器
- 自动登录微信或社交账号、绕过付费墙与访问控制
- 浏览器自动化 Agent、执行收藏内容中的代码
- 自建大模型、复杂工作流编排
- 必须依赖独立桌面客户端才能保存
- 订阅计费、多人多租户

移动端是独立的 iOS / Android App，与 Web 共用同一套收藏与检索能力；浏览器扩展、
数据导入导出等属于后续迭代，不在 V1 范围内。

## 目标用户

第一阶段面向个人知识工作者：

- 程序员与技术从业者
- 产品经理、设计师
- 研究人员、内容创作者
- 经常阅读文章和资料，但不愿意花时间整理的人

不要求用户具备 AI 或知识管理专业知识。

## 核心场景

### A. 看到内容，立即保存

复制 URL → 打开拾回 → 粘贴 → 保存。立即创建记录，后台完成解析、摘要与索引。
保存时不要求填写任何其他字段。

在手机上也可以直接从浏览器或社交应用的系统分享菜单选择拾回。分享内容里带链接即可保存；
没有网页链接的纯文字分享无法收藏。网络不可用时先留在本机待保存队列，联网后自动提交。

### B. 忘记标题，只记得大概内容

输入「之前看过一个开源项目，可以把网页内容交给 AI 分析，还能自动调用浏览器」。
返回最相关的收藏：标题、来源、原文链接、摘要、匹配原因、保存时间与处理状态。

### C. 记得文章中的某个细节

输入「有篇文章提到用 pgvector 配合全文检索，而不是只使用向量搜索」。
应优先命中正文中的讨论，而不是只匹配标题。

### D. 忘记收藏过什么

输入「我收藏过哪些和 AI Agent 浏览器自动化有关的文章？」。
只查询用户自己的收藏，不把互联网搜索结果混入个人记忆。

### E. 收藏微信公众号文章

尝试提取标题、作者、正文、发布时间、图片与正文链接。
受站点限制时保留 URL，并明确显示部分成功或失败，支持稍后重试。

### F. 重复保存

第二次提交相同链接时识别重复，不重复创建处理任务，并提供打开已有收藏的入口。

### G. 网页暂时无法解析

仍然保存 URL。用户可以重新解析、打开原网页或删除收藏。
解析失败永远不能导致收藏记录丢失。

## 产品边界

**用户不需要决定：**

- 内容属于哪个分类
- 使用什么标签
- 放进哪个文件夹
- 怎样组织知识库
- 记住文章标题

**系统负责：**

- 来源识别
- 内容获取与正文提取
- 内容理解与摘要
- 自动索引
- 语义搜索与结果解释
- 相关内容发现

最终希望形成的习惯是：

> 看到值得保留的内容，就交给拾回；想起某件事，就先打开拾回找。

## 后续可能（未承诺）

根据真实反馈再决定是否开发：

- 浏览器扩展、书签 / CSV 导入与 JSON 导出
- 搜索历史与个性化排序
- 更多专用解析器与高级筛选
- 更丰富的内容关联
- 更深入的移动端能力（后台静默保存、推送提醒）

这些功能不构成 V1 承诺，也不应提前扩大实现范围。
